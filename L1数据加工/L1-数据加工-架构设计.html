L1 数据加工 — 架构设计

用 LangGraph 把原始内容加工为结构化知识。核心是一张可观测、可重试、可换模型的基础分析图，加上严格的成本分级与缓存/重放机制。

1设计目标

💵

低成本

小模型初筛砍掉大头，再用中端模型深加工。

🧩

结构稳定

产物 schema 对上层稳定，模型/prompt 可换。

🔭

可观测可调

每节点输入输出留痕，便于调 prompt。

♻️

可重放

响应 L0 reprocess，幂等重跑。

🧱

不阻塞

失败可重试，不卡住整条管线。

🚫

垂直无关

只做通用理解，不含业务判断。

2组件

content.ingested ──▶ enrichment-worker ──▶ LangGraph 基础分析图 ──▶ 写产物 ──▶ content.analyzed
                          │                        │                      │
                     队列消费(Arq)            模型路由/缓存          content_base_analysis
                                                                    + embedding(pgvector)

3LangGraph 基础分析图

enrichment_graph (StateGraph)
state: {content_id, text, lang, partial...}

  clean_normalize            # 去噪/分段/长度评估
       │
  filter (cheap LLM)          # 低质/营销 → ignore=true → CANCELLED(短路)
       │ pass
  detect_lang
       │
  ┌────┴─────────┐  branch by length
  ▼              ▼
 analyze_full   split ▶ map(analyze_chunk) ▶ aggregate   # 长文分段再聚合
  └──────┬───────┘
  extract                     # one_liner/summary/key_points/quotes/entities (JSON 结构化输出)
       │
  embed                       # title+summary → vector → pgvector
       │
  base_tag                    # 通用主题/形式标签(与垂直无关)
       │
  persist ▶ emit content.analyzed
为什么用图：条件分支（长/短文）、map-reduce（分段聚合）、节点级重试与缓存、全链路 trace——这些正是 LangGraph 的强项，比一个大 prompt 可控得多。

4数据模型

content_base_analysis(
  content_id PK FK,
  one_liner, summary, key_points jsonb, quotes jsonb,
  entities jsonb, base_tags jsonb,
  embedding vector(1536),
  model, graph_version,        # 记录用哪个模型/图版本 → 重放判断
  tokens_in, tokens_out, cost, created_at )

enrichment_cache(            # 幂等/重放复用
  content_hash, graph_version, result_ref, created_at )

记录 model 与 graph_version：当图升级，可对比版本决定是否重跑；相同内容+相同版本直接命中缓存。

5模型分级与成本

节点模型档理由
filter 初评小模型（便宜）剔除 60-70% 低质，避免昂贵深加工
analyze/extract中端模型质量与成本平衡
embedembedding 模型低成本向量化
成本是 L1 的头号约束。三招降本：① 小模型初筛短路；② 只对通过初评的内容深加工；③ 缓存+重放复用。模型档位由 ConfigKey 配置，可随价格/质量变化切换。

6缓存 / 幂等 / 重放

  • 幂等：以 (content_hash, graph_version) 为键；重复处理直接命中，不重复花钱。
  • 重放：收到 content.reprocess 或 graph_version 升级时，按范围重跑；旧产物可保留对比。
  • 失败处理：节点级重试（指数退避）；多次失败标记并跳过，不阻塞队列。

7接口契约

# 输入事件  content.ingested {content_id, lang}
# 输出事件  content.analyzed {content_id}
# 产物      content_base_analysis (供 L2/L3 只读)
# 状态      WAIT_FILTER → WAIT_ANALYSIS → WAIT_SCORE | CANCELLED

8技术选型

编排LangGraph（StateGraph、条件边、map、重试）
运行Python · enrichment-worker（Arq/Celery 消费）
LLM分级调用（小/中模型），统一 LLM 客户端封装 + 路由
向量embedding 模型 → pgvector
可观测LangSmith 或自建 trace（节点级）

9部署

MVP：与其他 worker 合并为 worker 进程的一个 task 队列。规模化：独立 enrichment-worker 进程，按吞吐水平扩展；LLM 调用并发受限以控成本。

10风险

风险应对
LLM 成本超预算小模型初筛 + 缓存 + 并发限流 + 用量告警
结构化输出不稳定JSON schema 约束 + 校验 + 重试/降级
长文遗漏信息分段 map-reduce 聚合
模型升级回归graph_version 灰度 + 抽检对比
