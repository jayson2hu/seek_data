⇄独立开发说明（并行 + 后统一）

L1 不依赖 L0 完成即可开发。L1 取内容只经 ContentProvider 接口；开发期注入 StubContentProvider（读 fixtures），集成期换成 L0ContentProvider（调 L0 真实查询）。统一集成时只改这一处注入 + schema 合并，其余零改动。
接缝L1 的角色统一时怎么对接
内容输入经 ContentProvider 取Stub → L0 真实现，注入切换
触发消费 content.ingested接到平台事件总线即可
产物写 content_base_analysis + 发 content.analyzedL2 直接消费，无需改 L1
DB拥有 base_analysis/cache 表，只读 content_items迁移合并，无表冲突

3模块与接口契约（关键签名）

输入：ContentProvider（解耦 L0）

class ContentInput(BaseModel):
    id: int; clean_text: str; title: str|None; lang: str|None
    source: SourceRef; published_at: datetime|None; content_hash: str

class ContentProvider(Protocol):
    def get(self, content_id: int) -> ContentInput: ...

class StubContentProvider:        # 开发/测试用，读 fixtures
    def get(self, content_id): return load_fixture(content_id)
class L0ContentProvider:          # 集成用，调 L0 query.get_content
    def get(self, content_id): return adapt(l0_get_content(content_id))

产物契约（给 L2/L3，冻结）

class BaseAnalysis(BaseModel):
    content_id: int
    one_liner: str; summary: str
    key_points: list[str]; quotes: list[str]; entities: list[Entity]
    base_tags: list[str]; lang: str
    # embedding 存 pgvector，不在对外 schema

def persist(analysis: BaseAnalysis, meta: AnalysisMeta) -> None   # upsert by content_id
def emit_analyzed(session, content_id: int) -> None              # outbox: content.analyzed
冻结点：BaseAnalysis schema 与 content.analyzed 事件是 L2 唯一依赖。这俩定死后，L1 内部图怎么改都不影响下游——并行开发与统一的保证。

4LangGraph 图规格

build_graph(graph_version="l1-v1") -> StateGraph
  clean ─▶ filter ─(ignore?)─▶ [END: status=CANCELLED]
                  └─pass─▶ branch_by_length
                            ├ short ─▶ analyze_full ─┐
                            └ long  ─▶ split ▶ map(analyze_chunk) ▶ aggregate ─┤
                                  └─▶ extract ─▶ embed ─▶ tag ─▶ persist ─▶ emit
节点模型档: filter=cheap · analyze/extract=standard · embed=embed
缓存键: (content_hash, graph_version)；命中跳过 LLM
失败: 节点级重试(退避)；schema 校验失败 → 重试/降级；多次失败标记不污染产物
完整图说明见《L1 架构设计》§3；本处为可实现的装配规格。

7端到端冒烟自检（FakeLLM）

# make l1-smoke 流程（伪代码，零成本确定性）
def smoke():
    provider = StubContentProvider(); llm = FakeLLM(preset_responses)
    1. 取 fixture 内容(正常文章) → enrich(cid)
    2. assert content_base_analysis(cid) 存在且 schema 合法
    3. assert summary/key_points/entities 非空；embedding 维度=EMBED_DIM
    4. assert status == WAIT_SCORE
    5. 取 fixture(营销低质) → enrich → assert status == CANCELLED（短路）
    6. 再 enrich 同内容 → assert LLM 调用数==0（缓存命中）
    7. assert outbox 有 content.analyzed
    8. print "L1 PIPELINE: PASS" + 各节点 tokens/cost
✓ 验收 — make l1-smoke 输出 L1 PIPELINE: PASS。这是 L1 日常自检与 CI 的核心用例。

8完成判定（L1 DoD）

  • 用 stub + FakeLLM 独立端到端跑通并验收，无需真 L0/真模型
  • 初评剔除低质（CANCELLED）；正常文章产出完整结构化分析
  • 抽取严格符合 BaseAnalysis schema、与原文一致不臆造
  • 长文分段聚合不遗漏要点
  • embedding 入 pgvector；标签与垂直无关
  • content_base_analysis 完整 upsert；content.analyzed 不丢不重；状态正确
  • 模型分级生效、单篇成本可统计、超阈告警
  • 缓存命中省成本；版本升级可重放
  • 单元 + 图测试覆盖率达标，CI 全绿（不真调模型）
达成即：L1 可独立交付。统一集成时把 StubContentProvider 换成 L0ContentProvider、接平台事件总线、合并迁移即可。
