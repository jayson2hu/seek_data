L1 数据加工 — Content Enrichment Service

把 L0 的原始内容加工成结构化的"内容知识"：一句话总结、摘要、关键观点、金句、实体、向量、基础标签。这层与垂直无关、算一次、全局复用，是上层一切判断与体验的共同底料。

层级：L1 形态：内容理解服务 客户：L2 / L3 信条：与垂直无关 · 算一次

1是什么

L1 消费 L0 的 content.ingested 事件，对每条内容做通用的内容理解，产出结构化分析，写回平台供上层使用。它像一个"内容理解 API"：进去是原文，出来是机器与人都能高效消费的结构化知识。

🧹

清洗 + 初评

规范化文本；小模型剔除低质/营销内容，降低后续成本。

📝

基础分析

一句话总结、摘要、关键观点、金句、实体抽取。

🧲

向量 + 标签

embedding（语义召回）+ 基础打标 + 语言识别。

2核心价值

把"理解成本"从 N 次降到 1 次。同一篇内容，无论被多少个垂直、多少个产品消费，基础理解只算一次、存一份、所有上层复用。这既是成本优势，也是跨垂直综合能力的来源——大家用的是同一份内容知识。

3它的客户

客户从 L1 要什么
L2 判断/Agent摘要/观点/实体/向量作为评分、翻译、推荐的输入（不必重读全文）
L3 产品/站点详情页"秒开"展示摘要与观点；搜索用向量；早报用结构化字段
L0（反向触发）响应 content.reprocess，对历史内容重新加工

4能力范围

能力说明阶段
文本清洗/规范化去噪、分段、长度评估MVP
初评过滤小模型判定低质/营销，标 CANCELLED 不进深加工MVP
基础分析一句话/摘要/关键观点/金句/实体MVP
Embeddingtitle+summary 向量，写 pgvectorMVP
语言识别 + 基础标签lang + 通用主题/形式标签MVP
长文分段聚合超长内容分段分析再聚合，避免遗漏V1
播客转写音频 → 文本（ASR）后进同一管线V1

5产物契约（对上层）

  • 产物：content_base_analysis（one_liner / summary / key_points / quotes / entities / base_tags / embedding）。
  • 事件：完成后发 content.analyzed，驱动 L2 评分。
  • 状态推进：WAIT_FILTER → WAIT_ANALYSIS →（完成后）WAIT_SCORE。
  • 稳定性：产物结构对上层稳定；模型/prompt 可换，结构不变。

6"算一次"原则

L1 严格与垂直无关。凡是"对 AI Coding 而言好不好"的判断都不在这层（那是 L2）。L1 只回答"这篇内容客观上讲了什么"。这条边界一旦守不住，就会退化成"每个垂直各算一遍"，丢掉成本优势与综合能力。

8边界：L1 不做什么

  • 不做垂直判断：不打分、不判"值不值得读"——L2。
  • 不做翻译/推荐/问答——L2。
  • 不抓取/不存原文——L0。
  • 不面向终端——L3。
